# Development Guide

This guide details how to set up, run, test, and contribute to the **Restaurant AI Agent** repository.

---

## 1. Prerequisites

- **Python**: 3.12+ (tested with Python 3.12, 3.13, 3.14)
- **Node.js**: 18+ (tested with Node.js 20 and 24) & npm
- **Docker & Docker Compose**: Optional for local development; required for full containerized stack.

---

## 2. Supported Development Modes

The architecture explicitly supports two development modes:

### Mode A: Full Infrastructure Mode (Production-aligned)
- **Stack**: PostgreSQL 16 + Redis 7 + FastAPI Backend + Next.js Frontend.
- **When to use**: End-to-end integration testing, database migrations verification, or production builds.
- **Run via**: Docker Compose (`docker compose up --build`) or local native PostgreSQL and Redis instances.
- **Health status**: All components report `Connected`, overall status is `ok`.

### Mode B: Backend / Frontend Local Development Mode (No Docker Required)
- **Stack**: FastAPI Backend + Next.js Frontend.
- **When to use**: Rapid local development on Windows or systems where Docker is unavailable.
- **Resilience**: The backend and frontend start cleanly without crashing when PostgreSQL and Redis are absent.
- **Health status**:
  - Backend: `Connected`
  - Database: `Offline` (connection timed out gracefully)
  - Redis: `Offline` (connection timed out gracefully)
  - Overall status: `degraded` (Backend is operational, but persistence/caching dependencies are offline)

## 3. Environment Setup

Copy `.env.example` to `.env` in the repository root.

### On Windows (Command Prompt - cmd.exe)
```cmd
copy .env.example .env
```

### On Windows (PowerShell)
```powershell
Copy-Item .env.example .env
```

### On Linux / macOS
```bash
cp .env.example .env
```

> [!IMPORTANT]
> `.env` is ignored by Git and must never be committed. `.env.example` contains safe local-development defaults targeting `localhost:5432` and `localhost:6379`. Docker Compose automatically passes internal service hostnames (`postgres` and `redis`) through environment variables.

## 4. Running Locally on Windows (Without Docker)

### 4.1 Backend Setup (Terminal 1)

In Windows Command Prompt (`cmd.exe`):
```cmd
REM 1. Activate virtual environment
.venv\Scripts\activate

REM 2. Install backend dependencies
pip install -r backend/requirements.txt

REM 3. Start FastAPI server with live reload
.venv\Scripts\python -m uvicorn app.main:app --app-dir backend --reload --port 8000
```

Or in PowerShell:
```powershell
.\.venv\Scripts\activate
pip install -r backend/requirements.txt
.\.venv\Scripts\python -m uvicorn app.main:app --app-dir backend --reload --port 8000
```

- **Backend API**: [http://localhost:8000](http://localhost:8000)
- **Interactive Swagger Docs**: [http://localhost:8000/docs](http://localhost:8000/docs)
- **Health Check Endpoint**: [http://localhost:8000/api/v1/health](http://localhost:8000/api/v1/health)

### 4.2 Frontend Setup (Terminal 2)

In a separate Command Prompt or PowerShell window:
```cmd
cd frontend
npm install
npm run dev
```

- **Frontend Foundation Dashboard**: [http://localhost:3000](http://localhost:3000)

## 5. Database Migrations (Alembic)

Migrations are located in `database/migrations/versions/`.

### 5.1 Run Migrations
Apply all pending migrations to the database:
```bash
# From repository root
alembic upgrade head
```

### 5.2 Dry-Run SQL Generation (Offline Verification)
To inspect the raw PostgreSQL DDL generated by migrations without requiring an active database connection:
```bash
alembic upgrade head --sql
```

### 5.3 Downgrade Migrations
To roll back the Phase 2 migration:
```bash
alembic downgrade base
```
Or offline SQL dry-run:
```bash
alembic downgrade 0001_phase_2_foundation:base --sql
```

### 5.4 Migration Status & History
```bash
alembic current
alembic history --verbose
```

## 6. Development Database Seeding

The development seed script (`backend/app/db/seed.py`) populates a demo restaurant tenant, settings, staff, and customer records.

### 6.1 Safety Rules
- **Explicit Execution Only**: The seed script is NEVER executed automatically at application startup.
- **Production Guard**: Blocked when `APP_ENV=production`.
- **Idempotency**: Safe to re-run; will not create duplicate entries if the seed tenant already exists.

### 6.2 Running the Seed Script
With PostgreSQL running:
```powershell
$env:PYTHONPATH="backend"
.\.venv\Scripts\python.exe -m app.db.seed
```

## 7. Running Quality Checks & Tests

### 7.1 Backend Tests (pytest)
Runs all 65 automated tests covering Phase 1 health/caching/AI stubs, plus Phase 2 multi-tenant models, CRUD services, validation constraints, and tenant isolation:
```bash
cd backend
..\.venv\Scripts\pytest -v
```

### 7.2 Code Linting & Formatting (Ruff)
```bash
cd backend
..\.venv\Scripts\ruff check .
..\.venv\Scripts\ruff format --check .
```

To auto-format:
```bash
cd backend
..\.venv\Scripts\ruff format .
```

### 7.3 Frontend Production Build Validation
```bash
cd frontend
npm run build
```

## 8. Testing Phase 2 Endpoints Locally

### 8.1 Create a Restaurant
```bash
curl -X POST "http://localhost:8000/api/v1/restaurants" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Nile Breeze Grill",
    "currency": "EGP",
    "timezone": "Africa/Cairo"
  }'
```

### 8.2 Get Restaurant Settings
```bash
curl -X GET "http://localhost:8000/api/v1/restaurants/<RESTAURANT_ID>/settings"
```

### 8.3 Create a Customer
```bash
curl -X POST "http://localhost:8000/api/v1/restaurants/<RESTAURANT_ID>/customers" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Omar Farooq",
    "phone": "+201099887766",
    "email": "omar@example.com"
  }'
```

### 8.4 Create a Staff Member
```bash
curl -X POST "http://localhost:8000/api/v1/restaurants/<RESTAURANT_ID>/staff" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Sarah Mansour",
    "email": "sarah@nilebreeze.com",
    "role": "MANAGER"
  }'
```
